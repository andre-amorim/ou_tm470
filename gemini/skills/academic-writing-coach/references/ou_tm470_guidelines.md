# OU TM470 Submission Guidelines

These guidelines are derived from the "Helpful Hints" provided by OU TM470 Moderators.

## 1. Document Structure & Formatting
- **Single File:** Only submit a single Microsoft Word document (`.docx`). Never embed or attach separate files (e.g., zip files, PDFs) for appendices.
- **Appendices Location:** All appendices must be placed at the very end of the document, after the references list.
- **Landscape Pages:** Use landscape orientation for pages containing wide tables, large diagrams, or code listings to improve readability for the marker.
- **Cross-Referencing:** Create return links from the appendices back to the main text where they are referenced, improving navigation.

## 2. Progression (TMA01 -> TMA02 -> TMA03 -> EMA)
- **Cumulative Development:** Each assignment builds upon the previous one. TMA02 is essentially TMA01 with added/removed sections. The EMA is the final culmination.
- **Word Count Management:** The word limit (e.g., 4,000 for TMA02) is cumulative. To stay within limits, move older or less critical content (like initial project plans) to the appendices.
- **Highlighting Changes:** When submitting the next iteration, clearly indicate what has changed, been added, or deleted from the previous version (e.g., using font colors or MS Word revision features, subject to tutor agreement).

## 3. Code and Software Projects
- **Code Snippets:** Do **not** include all your source code. Only include snippets of complex, tricky, or particularly proud implementations. 
- **Explanation:** Briefly explain what the included snippet does and why it was chosen.
- **Formatting:** Avoid black backgrounds for code snippets as tutors may print TMAs.
- **Source Table:** Provide a comprehensive table in an appendix listing all source programs/modules with short descriptions. Include a structure diagram in the main text showing their relationships.

## 4. Evaluation vs. Testing
- **Testing:** Confirms that the software works during development.
- **Evaluation:** Assesses whether the final deliverable meets the original requirements and is "fit for purpose." User Acceptance Testing (UAT) or piloting the framework with real users is a strong form of evaluation.

## 5. Reviewing Work
- **Read Aloud:** Use the MS Word "Read Aloud" feature to audibly check the flow and readability of the text before submission.
