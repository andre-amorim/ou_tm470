# OER Design Pattern Analysis: OBC vs. Standard OER

## 1. Reference: Creating Open Educational Resources (OER)
*   **Key Source:** https://www.open.edu/openlearn/education-development/creating-open-educational-resources/content-section-2
*   **Core Principle:** Openness as a spectrum (Access, Reuse, Redistribute).
*   **Pedagogical Goal:** Transformative learning through open practice.

## 2. Pattern: OBC Startup Fund 2026 (PUB_10139_1.0)
*   **Structure:** Activity-Led / Workshop-Centric.
*   **Mechanism:** Uses external validation tools (SimVenture) integrated into the learning path.
*   **Outcome:** A tangible asset (Portfolio) rather than just "knowledge acquisition."

## 3. Application to TM470 (nixB Lab)
*   **The "Validation" Step:** Instead of just explaining Nix, the OER should require the learner to generate a `flake.lock` or a cryptographic proof of reproducibility.
*   **Workshop Integration:** Mirror the OBC "Upload" workshop. Learners should upload their `nix-shell` output to a shared space (or a GitHub fork) for "didactic peer review."
*   **Dual Value:** Just as OBC gives a "Statement of Participation," nixB should provide a "Reproducibility Certificate" (signed via the hardware security key).
