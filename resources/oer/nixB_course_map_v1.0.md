# Course Map: nixB – A Didactic Laboratory for Software Reproducibility

**Version:** 1.0 (OER Draft)  
**Date:** 16/Apr/2026  
**Level:** Undergraduate (HE Level 3 / OU Level 3)  
**Subject:** Software Engineering / DevOps / Reproducible Science  

---

## 1. Educational Rationale
The nixB course is designed as a "Didactic Laboratory" to address the growing complexity of software environments. By moving from imperative "manual" configuration to declarative "hermetic" environments, students will master the principles of software reproducibility and Infrastructure as Code (IaC).

## 2. Learning Outcomes (LOs)
Upon successful completion of this course, the learner will be able to:
- **LO1 (Knowledge):** Critically analyze the systemic failure modes of imperative software environments (e.g., Configuration Drift and Dependency Hell).
- **LO2 (Analysis):** Evaluate the "Mental Model" gap in software development using Donella Meadows’ systems thinking.
- **LO3 (Application):** Construct a deterministic, reproducible development environment using Nix flakes and the `uv` Python toolchain.
- **LO4 (Synthesis):** Orchestrate a local infrastructure stack (Bitcoin/Lightning) as version-controlled code.
- **LO5 (Evaluation):** Verify the fidelity of a software reproduction through automated infrastructure testing.

---

## 3. Modular Course Structure

### Unit 1: The Reproducibility Gap
- **Focus:** The philosophy of models and the "Mental Model" gap (Meadows, 2009).
- **Didactic Goal:** Transition the learner from "Technical Tinkering" to "Strategic Orchestration."
- **Multimedia Requirement:** "The Philosophy of Models" Infographic (Nano Banana).

### Unit 2: Declarative Foundations (Nix & uv)
- **Focus:** Functional package management and hermetic Python stacks.
- **Didactic Goal:** Demonstrate 100% reproducibility through declarative code (`flake.nix`).
- **Multimedia Requirement:** "Nix vs. Imperative Tools" Explainer Video (Google Vids).

### Unit 3: Local Infrastructure (Bitcoin & Lightning)
- **Focus:** Applying IaC principles to a complex, stateful technical stack.
- **Didactic Goal:** Managing system-level dependencies without host-system pollution.
- **Multimedia Requirement:** "Anatomy of a Hermetic Stack" Blueprint (Diagram Specialist).

### Unit 4: Verification & The Reflective Practitioner
- **Focus:** Automated testing and academic reflection.
- **Didactic Goal:** Validating the reproduction and documenting the process for academic assessment.
- **Multimedia Requirement:** "The Verification Loop" Audio Overview (Local TTS).
